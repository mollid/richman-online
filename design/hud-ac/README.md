# hud-ac · 动物森林 HUD 原型（2.5D，试验场，不接 client）

`design/game-ui-kit/kits/ac.css`（动物森林那套）当皮肤，给大富翁 Online 拼一块**对局中 HUD**，并把它 2.5D 化：three.js 画「场」，PixiJS 画「跟着场动的界面件」，DOM 留面板。
不动 `client/`、不改规则，只在这里试版面、密度、镜头与操作路径。

## 打开

浏览器直接开 `index.html`（**file:// 就行**，库已放本地 `vendor/`，不用起服务）。
**棋盘右上角**的「🧊 切方环棋盘 / 🌐 切回 2.5D」一键切换两种棋盘；`?board=flat` 或 `#board=flat` 是默认方环。
断网时 Google 字体掉回退，观感差一档（库不受影响）。

## 一屏骨架（不滚页）

```
┌ top    顶栏：视角岛民 + 回合/日期 + 🔔✈️ 三币 + 页签跳转 ─────────┐
│ status 状态条（一行）：日期·物价·行情带(可横滚)·停牌·奖池·棋盘切换 │
├ board  2.5D 舞台（ResizeObserver 自适应）+ 图例   │ side 侧栏 6 页签 │
├ dock   选中格块 │ 行囊一行(44px) │ 主操作 + 更多 + 被挡住 ─────────
└──────────────────────────────────────────────────────────────────┘
```

| 区 | 内容 | 组件 |
| --- | --- | --- |

## 为什么这么排（本轮改动依据）

改前实测的问题 → 现在的做法：

- **环心卡片压在棋盘上** → 拆成两处：脚下/选中格进 dock（离主按钮最近），状态类信息进「岛况」页签。舞台内只留镜头条与提示，且它们落在草地/边框上，不盖格子。
- **13 个按钮同排、主操作在视口外 1364px** → 主操作唯一（按 掷骰 > 买地 > 加盖 > 结束回合 择一放大），次操作折进「⚙️ 更多动作」，灰态折进「🚫 被挡住 n」并逐条写明被哪条规则挡（progressive disclosure，门控仍读 `availableActions`）。
- **行囊被挤成 1 列 66px** → dock 三段定宽，行囊改横向单行滚动，单元 44×44。
- **整页要滚 2.2 屏** → 骨架改 `100dvh` 网格，滚动只发生在侧栏面板内部与行情带/行囊（`overscroll-behavior: contain`）。
- **浮层常驻挡图** → 格子浮层改跟随指针、只在悬停时出现；点击改为把详情钉进 dock。
- **z-index 乱数** → 定刻度：10 舞台内 / 20 舞台浮层 / 30 dock / 40 弹层与提示 / 50 吐司。
- 另加：`ResizeObserver` 跟容器（不只 window resize）、WebGL canvas 补 `role="img"` + `aria-label`、页签 `role=tablist` + `aria-selected` + ←/→ 键、吐司 `aria-live=polite`、岛民行 `role=button` 可 Enter/Space、数字 `tabular-nums`、`prefers-reduced-motion` 降级、切到方环时 `setPaused(true)` 停掉 WebGL 不空转。

## 本轮精细化（2026-10-10）

对同一套界面做了一轮**纠错 + 精细化**，两条骨架规则没动。完整规格见仓库根 `大富翁Online-HUD精细化规格.md`，前后对比图见 `preview/`。

修掉的都是「写了但实际没生效」的隐性缺陷，肉眼看不出来，是量出来的：

- **单格地名字一个都没显示** —— 贴面按 `DEPTH`(0.5) 写死高度，但 `ExtrudeGeometry` 的 bevel 把实际顶面抬到 0.55，贴面埋在格子里。改成 `geometry.boundingBox.max.y` 实测。
- **持有者标色完全不可见** —— 同一个根因（着色块 y=0.06、描边 y=-0.03 都在格子体内）。改成格子下半部套一圈彩色台座。
- **账本「资产清单」整张表在 1440×900 下消失** —— `.hud-tablewrap` 是滚动容器，作为纵向 flex 子项自动最小尺寸为 0，被压成 0 高。加 `flex: none`。
- **六支股现价整条被挤没**（1150px 下宽度 0）—— 行情带 `min-width:0` 是唯一可压缩项。改 `min-width:200px`，并把「棋盘切换」挪到棋盘右上角、「原型标」挪到顶栏。
- **面板内分隔标题对比度 1.05:1**（ac.css 的浅色分隔标题是给绿色页面底设计的）—— 在 `.hud-shell .ac-panel__bd` 作用域内覆写。
- 另有：2.5D 名牌被舞台圆角裁掉、行囊标题被裁成半截字、侧栏面板标题折行。

观感上做了：**中央岛心广场**（沙径外环 + 十字小径 + 木告示牌 + 骰盘，骰子 0.86→1.15 并抬到草地之上）、**名牌改奶油底 + 玩家色圆点**、**图例改单行真色块（色值与 `world.js` 的 `GROUP_HEX` 同源）**、**岛民行压成两行 + 6px 细条**。

布局上：舞台不再强制 1:1（宽屏不再留空壳，镜头按宽高比补偿），**≥3:2 时图例自动切成棋盘右侧竖导轨**；方环环心不再压格子（5 列 → 0/64）。

复测：1150×1145 / 1440×900 两档、6 个页签、两种棋盘，横向与纵向溢出均为 0，控制台无报错。

补测窄视口时另抓到**三个既有缺陷**（都与本轮改动无关，是量出来的）：

1. **1024×768 下 2.5D 棋盘只剩 6px 边框高** —— 单列堆叠后 `.d25-host` 是 `flex:1 + min-height:0`、`.d25-stage` 又是 `height:100%`，百分比高度对不定高父级无解，整个舞台塌成图例那一条 30px，canvas 实测 **0px**。给舞台补一个确定高度后恢复 **568px**（`preview/cam-5-1024x768-fixed.png`）。
2. **「镜头聚焦中」提示条解锁后不消失** —— `hidden` 的 `display:none` 来自 UA 样式表，被 `.hud-camtag { display: inline-flex }` 这个作者样式盖掉。补 `.hud-shell [hidden] { display: none !important }`。
3. **≤960px 横向溢出 621px（390px 视口）** —— 真凶是顶栏与状态条的 `flex-wrap: nowrap`（8 个 `flex:none` 的 chip 自己就超一屏），外加 dock 在堆叠态仍用三列模板。相机条因为 `grid-area` 横跨三列、会把 dock 总宽原样继承，**看起来像它的锅，其实是背锅**。修后 390×844 溢出 0。

改媒体查询时还踩了一次**源码顺序**的坑：基础 `.hud-dock` 规则在文件上方、与覆盖规则特异性打平（0,1,0），同特异性下由源码顺序决定胜负 —— 媒体查询写在上面会被基础规则反过来覆盖（表现是「改了等于没改」，溢出数字一模一样）。现全部挪到文件末尾并写了注释。

## 相机系统（2026-10-10 第二轮）

需求：轮到某位玩家操作时，相机先**平滑拉近聚焦**到该玩家 → 转入**跟随**该玩家 → 全程顺滑过渡 → **视角完全停稳后才允许操作**，期间**屏蔽输入**。

- **状态机**（`world.js`）：`idle`（自由视角）/ `intro`（聚焦入场，`locked=true`）/ `follow`（指数平滑跟随）。补间用 `easeInOutCubic`，时长 `CAM.introMs = 1150ms`。
- **输入闸门有两条路**：`world.bindEvents()` 里 `pointerdown/move/up/wheel/keydown` 全部 `if (locked) return`；HUD 侧由 `onCameraLock` 回调切 `.hud-shell--locked`，并在 `shell` 上挂**捕获阶段**点击拦截 —— 只靠 `cosmetic()` 里判断会漏掉页签、挂出、商店这些旁路。唯一放行的是「🎥 镜头巡演」按钮（它是驱动镜头用的）。
- **注视点夹取**：`clampToBoard()` 把跟随点限制在离棋盘中心 `followClamp = 8` 以内。近景视野只有 ~29 单位，直接钉在角落棋子上会把棋盘甩出画面。代价是「注视点 ≠ 棋子位置」，这是**故意**的 —— 「现在轮到谁」由地面高亮环 + 名牌金底承担。
- **三条指示永远同指一人**：相机目标、地面高亮环、名牌金底都取「跟随中的人」（`tokenAnchors().cur` 优先取 `followPid`）。换人后实测三者一致。
- **入口**：`D25World.focusPlayer(pid, opts)` 是唯一入口；HUD 的 `syncStage()` 在**回合指针变化**时自动调它（判据是 `currentPlayerIndex` 变没变，不是比对 `activePid` —— 巡演会把 `activePid` 挪走，那样每次 render 都会把镜头拽回来）。
- **原型不给「结束回合」按钮**：`view.actions` 是引擎快照派生的，原型重算不了，做成按钮会让人以为能推进回合。改用两个自检钩子：`__camTour()`（镜头巡演四位玩家）与 `__setTurn(i)`（走「换人 → 自动聚焦」真实路径，仅脚本用）。

完整规格见仓库根 `大富翁Online-相机系统规格.md`，截图见 `preview/cam-*.png`。

## 正交等距近景（2026-10-10 第三轮）

需求（附《環島大富翁》截图）：**人物站在棋盘上，周围只显示几格。**

- **另开一台正交相机** `orthoCam`（`PerspectiveCamera` 留给战略俯视）。透视投影下越远越小，
  5 格进深里近处和远处格子尺寸差肉眼可见，「等距」的前提直接失效，正方形格子也不再是规则 2:1 菱形。
  `camMode: 'top' | 'iso'`，舞台工具条「🔍 近景等距 / 🗺 回到全盘」切换。`camera` 变量按模式重新指向，
  所以 `raycast` / `project` 一行没改。
- **标准等距角 az 45° / el 35.264°**（`= atan(1/√2)`），视线归一化后正好 `(1,1,1)/√3`，
  三个轴投影等长。`ISO.view = 9.6`（SPACING=2 → 4.8 格进深），实测同屏 **7 格**（4 名玩家各测一次，全一致）。
- **`aimY = 1.0`**：注视点钉在格面时人物整个长在中心线以上，近景看着就是「人偏高、下面空一截」。
  把注视点**连同相机位姿**一起抬 1.0 —— 正交投影下等价于画面刚性下移。只抬注视点会让相机仰起、菱形被压歪。
  实测人物投影 NDC `(0.000, 0.026)`。
- **模式互切三处坑**（详见规格文档 §3）：① 必须做「透视距离 ↔ 正交视野」等效换算，否则换相机那一帧画面高度从 42 跳 22；
  ② `ISO.viewMax` 要给到 80 —— 上限存在的意义是给滚轮一个边界，不是给模式互切设路障；
  ③ `topMemory` 不能「切走那一刻才采样」（可能正处在补间中间），要在 `applyCam()` 里「不在补间里就持续记录」。
- **横向封顶 `ISO.maxAspect = 1.5`**：竖直视野固定，横向 = 竖直 × 舞台宽高比，本来是没上限的。
  用户那台是 2.09:1，实测一次铺开 **14 格**，「周围只显示几格」被稀释成一条长带。
  现在横向最多给到竖直的 1.5 倍，超出的宽度交给海面填充 —— 1150×1145 / 390×844 / 1440×900
  的 7 / 7 / 9 格**都不变**，只有 1024×768 从 13 收到 11、用户那台从 14 收到 11。
  小地图取景框改读 `cameraState().aspect` 跟着一起夹，否则框会比实际视野宽一截。
- **近景需要、俯视不需要的场地**：格子改成薄片（`DEPTH 0.5 → 0.20`）、每格加奶油台座（近景里棋盘和地面之间唯一的视觉分隔）、
  程序化地面纹理（固定种子 PRNG，**顶面 UV 直接取形状坐标**所以天然按 1 世界单位平铺）、
  海 → 浅滩 → 岛三层 + 环岛浪花、环内树带（近景只看得到贴着棋盘那一圈，广场在 18 单位外根本不在画面里）、
  椰林 / 礁石 / 花丛 / 民居。全部走 `InstancedMesh`：**draw call 反而比补细节之前更少**（250+ → 234）。
- **人物重做**：抬头 `HEAD_TILT = -0.34`（等距俯视 35.264°，正视的头只能看到头顶）、
  眼嘴按球面反解贴点、帽檐从球心推到 0.275（原来埋在头里、帽顶成了一颗光头）、
  手臂压低到髋部 + 略深一档的玩家色 + 单独给肤色的手。
- **小地图**（`drawMinimap()`）：近景只看得到 7 格左右，方位感会丢。右下角画 64 格环 + 持有者描边 +
  **跟着方位角转的橙色取景框** + 四名玩家圆点。iso 模式显示，同时禁用四个俯视视角预设
  （它们走 `setView()`，会先退回 top）。

## 工具条点不动 · 真鼠标修的一课（2026-10-10 第三轮补）

用户实测反馈：**「复位、正俯视、斜 45° 所有按钮点了都是无效的，也没看到小地图和近景视野」**。

- **根因**：`world.js` 的 `bindEvents()` 在 `pointerdown` 里对 `host` 调 `setPointerCapture(e.pointerId)`，
  而 `host` 就是 `.d25-stage` —— 舞台工具条（复位 / 正俯视 / 斜 45° / 低角度 / 近景等距 / 镜头巡演）**全长在它里面**。
  指针在按钮上按下时被 stage 抢走，随后的 `mouseup` / `click` 被重定向到 stage，按钮自己的 `onclick` 永远不触发。
  实测事件落点：

  ```
  工具栏按钮（在 .d25-stage 内）：        dock 按钮（在 stage 外）：
    pointerdown → BUTTON  ✅                pointerdown → BUTTON  ✅
    mousedown   → BUTTON  ✅                mousedown   → BUTTON  ✅
    mouseup     → DIV.d25-stage  ❌         mouseup     → BUTTON  ✅
    click       → DIV.d25-stage  ❌         click       → BUTTON  ✅
  ```
- **修法**：加 `isControl()` 判定；`pointerdown` 起点在控件上时直接 `return`（不接管指针，把 click 留给按钮）；
  `pointermove` 同样跳过（否则鼠标划过按钮时，背后那片格子会莫名其妙亮起来）。
- **为什么三轮没查出来**（这条比 bug 本身重要）：此前所有点击类断言都用 `element.click()`。
  它是 **DOM 直调、不过命中测试**，所以「自动化全绿、真人全废」。
  ⇒ 凡「点击」断言，一律用真鼠标（`locator.click()` / `page.mouse.*`）**并断言事件落点**，
  已固化成 `tools/interaction-smoke.mjs`。
- 顺带修掉另外三处：**「🎥 镜头巡演」在俯视模式下几乎看不出变化**（新增 `focusView()` 显式给机位，
  原来只平移注视点）、**「回到全盘」失效**（top 下 `use.dist=false` 导致相机被留在近景距离）、
  **锁定态可能永久假死**（`onFrame` 里每帧跟 world 真实状态对齐一次兜底）。
- **第二处拦截（修完第一处才浮出来）**：`.d25-bar` 的 `max-width: calc(100% - 16px)` 没给右上角
  「🧊 切方环棋盘」按钮留位。相机读数 chip 一长（带「▶ 聚焦中」，或近景读数带了「·N格」），
  整排按钮被往右推，最后那颗「🔍 近景等距」的中心就落进切换按钮的命中区 ——
  真鼠标点下去报 `hud-bswitch intercepts pointer events`，而按钮看起来完全正常。
  改成 `calc(100% - 126px)`（按钮宽 99.4 + 右边距 10 + 间隙）。
  这一处的阴险程度不比第一处低：它**只在读数变长的那一刻**发生，静态截图完全看不出来。
- **测试要掐掉 Google Fonts**：`index.html` 从 fonts.googleapis.com 拉字体，网络一慢，
  `page.goto` 被样式表阻塞到超时、`page.screenshot` 卡在「waiting for fonts to load」。
  冒烟测试里 `page.route` 直接 abort，换来不依赖网络的可复现结果；代价是文本落到 fallback 字体、
  字宽略宽，工具条会多折一行 —— 判读截图时要知道。

## 已知粗糙处

- 图形全是 emoji 占位（格面类型图标、棋子、骰子点、行囊道具）—— 地名的**文字**已修好并上格面，但图标仍未换成图集资源。
- 中文圆体缺字：`--ac-ui` 走 M PLUS Rounded 1c，中文落回系统黑体。
- dock 弹层里的次操作按钮 40px 高，未达 44px 触控标准（弹层内密度优先；dock 上的三个按钮与行囊单元已 ≥44）。
- 斜 45° 轴测下单格仍偏小 —— 已由第三轮的**近景等距**部分解决（`ISO.view = 9.6` 时同屏 7 格、
  格面文字清晰）；但这是另一套镜头，不是把原来那套俯视拉近。真正的「全局 / 半区 / 单格」三级分级仍未做。
- **近景可视格数随舞台宽高比变化**（1150×1145 是 7 格、1440×900 是 9 格、1024×768 是 13 格）：
  视野是按竖直短边定的。想在任何宽高比下恒定，得改成按短边取景，代价是宽舞台两侧浪费。
- **近景里人物的造型仍是程序化低模**（圆柱 + 锥叶的树、规则形状的礁石），
  只对齐了参考图的**构图与内容**（薄片格子 / 奶油边 / 椰林 / 花丛 / 岛与海），风格仍是干净的 3D 低模，
  不是手绘像素风。
- **软件渲染下 2~5 fps**（2300×2290 像素 + PBR 光照）。这是截图/自动化环境的问题，真机 GPU 无此压力；
  但自动化脚本要给它足够长的等待时间 —— 一张截图本身就要 1 秒以上，想抓「补间途中」的帧
  必须先冻 rAF 再用 `renderOnce(dt)` 手动推进。
- 侧栏 6 个页签在 320px 栏里刚好排满，再加就得改下拉。
- 宽屏（≥3:2）下棋盘列横向仍有余量：棋盘是方的、高度已顶满，横向必然多出来，目前靠图例导轨 + 舞台渐变底填充。
- **跟随期注视点 ≠ 棋子位置**（差 8~15 单位，取决于棋子离环心多远）。这是 `followClamp` 夹取的必然代价：不夹取就只能看一个格子。真要「贴身跟随」得先做镜头分级（全局 / 半区 / 单格），或把棋盘改成滚动视口。
- **跟随态下拖拽只转方位角/俯角，不会脱离跟随**（`follow` 只写 `target.x/z`，不碰 `az/el/dist`）。想彻底自由看局要点「复位 / 正俯视…」——`setView()` 会先 `releaseFollow()`。
- 巡演只动镜头、不改回合（`view.actions` 重算不了），所以巡演到别人身上时，dock 的「脚下格」仍是快照基准回合的那位。相机条上写了「原型只动镜头 · 不改回合」。
- 单帧补间步长在软件渲染（~11fps）下最大 6~8 单位。这是**帧率回落**、不是曲线问题：按 1/60 定步长实测单帧最大 0.686 单位、平均 0.232、相邻步长最大变化 0.0386（详见规格文档验证表）。
- `≤960px` 为纵向堆叠降级布局（顶栏/状态条换行、dock 单列），是本轮顺手补的健壮性兜底，**不是目标视口**。390×844 实测横向溢出 0，但版面是按「手机上能看」而非「手机上好用」的标准收的。
- **`isControl()` 是一张要维护的白名单**（`button, a, input, select, textarea, label, [role="button"], .d25-bar`）。
  以后再往 `.d25-stage` 里加非 `<button>` 的自定义控件（比如 `<div onclick>`），必须补 `role="button"` 或加进选择器，
  否则又会退化成「指针被 stage 抢走、点了没反应」。更稳的做法是把拖拽的 `setPointerCapture` 从整块 stage
  收窄到棋盘 canvas 上，从根上不跟 UI 抢指针 —— 需要拆分舞台层级，本轮没做。
- **工具条右侧的 126px 让位是硬编码**（`max-width: calc(100% - 126px)`），
  按「切方环棋盘」按钮当前字号/内距量出来的（99.4 + 10 + 16）。那颗按钮一改文案就要跟着改，
  否则又会压到一起。根治办法是把切换按钮并进 `.d25-bar` 的 flex 流（`margin-left:auto`），
  让 `flex-wrap` 自己算 —— 但它同时被方环形态复用、位置语义不同，本轮没动。
- 真客户端是 Pixi 等距棋盘（`client/src/game/BoardRenderer.ts`），这版是 three+Pixi 的另一条路线，合并要另开工。
