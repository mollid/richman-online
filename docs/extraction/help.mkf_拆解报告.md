## 二、MKF 容器结构

```
[0x00]  u32  index_table_offset = 362852   ← 索引表在文件尾部的偏移
[0x04]  第 0 个资源块开始 ...
        ...
[362852] 索引表：100 个 u32，依次为每个 chunk 的绝对偏移
```

- 每个资源块 = **16 字节头** + 数据：
  `uncompressed_size(u32) | compressed_size(u32) | f2(u32) | f3(u32)`
- 数据从块偏移 +16 字节开始。
- 文本块（#1–#99）的数据区为 **BIG5 编码**的繁体中文，直接解码即可。

## 六、技术方法（可复用于其他 MKF 文件）

1. **容器解析**：读文件头 4 字节得索引表偏移 → 读尾部 N 个 u32 得各块偏移 → 每块读 16 字节头。
2. **文本提取**：`chunk[i]` 数据区 = `data[off+16 : off+chunk_size]`，BIG5 解码即帮助文本。
3. **压缩块处理**（如 `map.mkf` 的压缩块）：需 rich4 私有自适应霍夫曼解压算法（`csrc/mkf/mkf_decompress.c`），用 MSVC `cl.exe` 编译为 `mkfdec.exe` 后可对任意压缩块解压（已在上轮 map.mkf 任务中验证有效）。help.mkf 不含压缩块，故未使用。
